# 화면 규칙: 도움말·입력도우미·중복 입력 없애기

대표 지시(2026-11-08)에 따른 규칙입니다. 모든 화면에 적용하고, 지키지 않으면 타입 검사나 `tests/unit/help.test.ts`가 실패합니다.

1. "도움말 및 입력도우미를 철저하게 하라."
2. "중복입력은 철저하게 피한다. 가능한 한 앞선 입력전표들의 값을 불러와 사용한다."

## 도움말

대표 지시(2026-11-08)에 따라 도움말을 화면에 따로 펼쳐 두지 않습니다. 화면 제목, 패널 제목, 입력 칸 이름 옆에 **?** 단추를 두고, 누르면 **오른쪽 도움말 창**(`src/app/_help-drawer.tsx`)에 그 도움말이 열립니다.

- 창은 화면을 막지 않습니다. 넓은 화면에서는 본문이 왼쪽으로 비켜서므로, 도움말을 보며 계속 입력할 수 있습니다.
- 같은 ? 를 다시 누르거나 Esc 를 누르면 닫힙니다.
- 창 안의 용어를 누르면 그 용어 설명으로 넘어가고, '뒤로'로 돌아옵니다.

- **화면 도움말**: `src/modules/help/pages.ts`의 `PAGE_HELP`에 목적, 쓰는 사람, 순서, 요령, 자주 묻는 질문, 관련 조항, 용어를 적습니다. `ROUTE_HELP`에 경로를 잇고, `PageTitle`에 `help` 키를 넘깁니다. 이 키는 필수입니다.
- **칸 도움말**: `src/modules/help/fields.ts`의 `FIELD_HELP`에 이름, 한 줄 안내, 예시, 자세한 설명(?), 형식, 문구 넣기, 글자 수를 적습니다.
- **패널 도움말**: `src/modules/help/panels.ts`에 적습니다. 제목이 있는 `Card`에는 `help`를 꼭 넘깁니다. 빠지면 테스트가 실패합니다.
- **용어·정책값·전결·상태 설명**: `src/modules/help/glossary.ts`에 둡니다. 정책값이나 전결 업무를 새로 더하면 설명을 적지 않을 경우 타입 오류가 납니다.
- **도움말 센터**: `/help`에서 위 내용을 모두 찾을 수 있습니다.

## 입력도우미 (`src/app/_input.tsx`, `src/app/_assist.tsx`)

- 화면에 `<input>`, `<select>`, `<textarea>`를 맨 태그로 쓰지 않습니다. 쓸 수 있는 부품은 다음과 같습니다.
  - `TextField`, `TextAreaField`, `NumberField`, `DateField`, `PasswordField`, `SelectField`, `CheckGroup`
  - 예외: 숨은 칸, 찾기 칸(`type="search"`), 저장하지 않는 미리 보기 칸(`data-assist="preview"`)
- 폼은 `AssistForm`으로 감쌉니다. 다음을 해 줍니다.
  - 서버가 오류로 돌려보내면 적은 값을 되살립니다.
  - 긴 양식(`draft`)은 이 기기에 임시 저장해 둡니다.
  - 저장하지 않고 나가려 하면 경고합니다.
- 금액은 `NumberField`에 단위를 원으로 줍니다. 쉼표, 한글 읽기(150만 원), 범위, 지금 값과의 차이를 보여 줍니다.
- 서버가 저장을 막는 규칙(필수 동의, 형식, 확정 안내 체크, 한도 등)은 저장 단추 위 점검 목록으로 미리 알립니다(대표 지시 2026-11-08). 항목을 누르면 그 칸으로 갑니다. 예: `src/app/consults/save-check.tsx`. 서버 검사와 같은 규칙을 씁니다.
- 고른 값에 따라 나타나는 칸은 `ShowWhen`으로 그립니다. 안 쓰는 칸은 그리지 않아 숨은 필수 칸이 저장을 막지 않습니다.

## 중복 입력 없애기(불러오기)

- 새 전표는 앞 전표에서 시작합니다. 화면 주소에 `?from=<앞 문서 id>`를 주면, 서버가 그 문서 값을 `defaultValue`로 채웁니다. 채운 칸에는 `from="<문서 번호>"`를 넘겨 "○○에서 불러옴"을 표시합니다.
- 앞 전표의 값은 다시 묻지 않습니다. 필요하면 숨은 칸이나 출처 id로만 넘깁니다. 예외는 비밀번호 확인 칸입니다.
- 1차 수리 흐름의 연결은 다음과 같습니다.
  - 상담(CS) → 접수(RO) → 견적(ES) → 작업(WO) → 검사 → 출고 → 청구(IV)
  - 각 단계는 앞 번호를 고르면 고객, 차량, 보험(보험사·사고접수번호·과실·자기부담금), 품목, 금액을 그대로 가져옵니다.
  - 고객과 차량은 전화번호나 차량번호로 찾아 다시 씁니다.
- 결재 근거 번호처럼 앞 문서를 가리키는 칸은 `suggestions`(목록)로 고르게 합니다. 서버에서도 실제로 있는 문서인지 확인합니다.
- 지금 들어간 예시는 다음과 같습니다.
  - 정책값·전결 화면에서 개정 요청서를 열면 대상과 현재 값이 채워집니다.
  - 확정된 요청서에서 설정 화면을 열면 값, 근거 번호, 사유가 채워집니다.
  - 반려 문서는 "고쳐서 새로 올리기"로 내용을 불러옵니다.
  - 대리인은 지난번에 정한 사람이 기본값입니다.

## 화면 배치

대표 지시(2026-11-08)에 따라 화면은 브라우저 폭을 다 씁니다. 화면에 최대 폭을 두지 않습니다. 넓은 화면에서는 칸을 여러 열로 나란히 놓습니다. 예를 들어 현재 내용과 바꿀 내용을 나란히 두고, 결재 문서는 본문과 이력을 나란히 둡니다.

- 메뉴는 왼쪽에 둡니다(`src/app/_sidebar.tsx`, 구조는 `src/app/_menu.ts`). 묶음 순서는 사내 표준서 장 순서를 따릅니다.
- 메뉴 묶음은 기본으로 접혀 있고, 지금 화면이 든 묶음만 저절로 펼칩니다. 사용자가 펼친 묶음은 그 기기에 기억합니다(대표 지시 2026-11-08).
- 도움말 센터와 내 계정은 맨 아래 '도움말·내 정보' 묶음에 둡니다(업무 메뉴에 섞지 않음).
- 개발 예정 화면은 흐리게 보이고 단계(1차·2차·3차)가 붙습니다. 화면을 만들면 `href`를 채웁니다.
- 태블릿·휴대폰에서는 ☰ 로 메뉴를 엽니다.
- 위쪽 줄에는 알림, 도움말, 내 이름, 로그아웃만 둡니다.
